## SA-12 · مصفوفة الاعتماد وحدود الخصم — P1 · [Pending بند 33] (القيم [Open])

**Epic story:** كصاحب شركة أريد أحدد إمتى يحتاج الخصم أو الطلب اعتماد ومين يعتمده، من غير ما أغيّر كود.

### الشاشات
| ID | الاسم | Route |
|----|-------|-------|
| SCR-APR-01 | قواعد الاعتماد | `/super-admin/policies/approvals` |
| SCR-APR-02 | محرر قاعدة | Drawer |
| SCR-APR-03 | محاكاة قاعدة [New] | Dialog |

**القاعدة:** (محفّز) ← (سلسلة). المحفّزات: نسبة خصم · قيمة طلب · طلب استثنائي. السلسلة: **Sales Manager ← General Manager** عند اللزوم.

### Use Cases
**UC-APR-01 · إنشاء/تعديل قاعدة** — اختيار المحفّز + العتبة (حقل رقمي **فاضي**) + السلسلة ← حفظ ← Step-up ← `POLICY.APPROVAL_CHANGED`.
**UC-APR-02 · محاكاة** — «طلب بخصم X% وقيمة Y، هيروح لمين؟» ← النتيجة بالخطوات (لا يُنشئ طلبًا).
**UC-APR-03 · تصعيد عند التأخير [New]** — مدة التصعيد **{Open}** ← يرسل للخطوة التالية/تنبيه.
**UC-APR-04 · تطبيق القاعدة (سلوك النظام)** — عند إنشاء طلب بيع يتخطى الحد ← يُنشأ `ApprovalRequest` ← يظهر في SA-16 للمعني.

**US-APR-01** AC: لا حفظ بعتبة فاضية لقاعدة مفعّلة · القاعدة غير المفعّلة لا تؤثر.
**US-APR-02** AC: التغيير لا يؤثر على طلبات اتقدّمت قبله (تُقيَّم بقاعدة وقتها).
**BR-APR-01** قابل للتوسع لاحقًا لسند الصرف (بند 42) والمرتبات (بند 44).

## SA-13 · ترقيم المستندات وقوالبها — P0/P1 · [Pending بنود 14 و47]

### الشاشات
| ID | الاسم | Route |
|----|-------|-------|
| SCR-NUM-01 | جدول الترقيم | `/super-admin/policies/numbering` |
| SCR-NUM-02 | محرر الترقيم | Drawer |
| SCR-NUM-03 | قوالب المستندات (11 قالب) | `/super-admin/policies/templates` |

**الأنواع:** `INV-` `DN-` `WO-` `ST-` `PS-` (بند 14) + `QT-` `RV-` `PV-` `PR-` `AG-` `SOA-` `PAY-` (بند 47) و`PF-` في الديمو. **`SO-` مستخدمة في الديمو وغير مدرجة** (قرار 7).

### Use Cases
**UC-NUM-01 · تعديل بادئة/شكل** — الشكل في الديمو `PREFIX-YYYY-NNNN` ← خيارات: السنة، تصفير سنوي، عدد الأصفار ← معاينة حية ← فحص تكرار ← حفظ ← `POLICY.NUMBERING_CHANGED`.
**UC-NUM-02 · قفل التعديل [New]** — بعد أول مستند صادر من النوع، الشكل يتقفل؛ تغيير البادئة لا يعيد ترقيم القديم.
**UC-NUM-03 · قالب المستند** — لكل نوع: لغة (عربي/ثنائي) · إظهار الختم · إظهار التوقيع ← معاينة A4 ← حفظ.
**UC-NUM-04 · توليد الرقم (سلوك النظام)** — تسلسل مستقل لكل نوع، atomic، بلا فجوات متوقعة أو تكرار.

**US-NUM-01** AC: لا بادئتين متطابقتين · الرقم يتولّد بدون تكرار حتى مع طلبين متزامنين.
**US-NUM-02** AC: ملف PDF عادي **ليس** فاتورة إلكترونية معتمدة، ولا يُوصف كذلك (Approved).
**BR-NUM-01** البادئات الحالية غير نهائية قبل اعتماد المالية والتشغيل.

## SA-14 · إعدادات المالية — P1 · [Pending بنود 38–42] (القيم [Open])

> **أين تعيش الشاشة؟** `finance-hr.html` فيه إعدادات، وPRODUCT يقول الإعدادات المركزية من Super Admin. **قرار 5.** هنا بنفترض: تُعرض في Super Admin وتتنفّذ بصلاحية المالية.

### الشاشات
| ID | الاسم | Route |
|----|-------|-------|
| SCR-FIN-01 | الضريبة | `/super-admin/policies/finance/tax` |
| SCR-FIN-02 | طرق الدفع والشيكات | `.../payment-methods` |
| SCR-FIN-03 | البنوك والخزائن | `.../banks` |
| SCR-FIN-04 | السنة المالية والحسابات | `.../fiscal` |
| SCR-FIN-05 | سياسة التأخير | `.../overdue` |

### Use Cases
**UC-FIN-01 · ضبط الضريبة** — النسبة **{Open: المحاسب القانوني}** · شاملة/غير شاملة · إعفاءات أصناف ← `POLICY.FINANCE_CHANGED`. (14% في الديمو تجريبية.)
**UC-FIN-02 · تفعيل طرق الدفع** — نقداً · تحويل · شيك · بطاقة · حالات الشيك: مستلم · تحت التحصيل · محصَّل · مرتد · ملغى.
**UC-FIN-03 · إدارة بنوك وخزائن** — أكتر من حساب/خزينة · مع صلاحيات إنشاء/اعتماد/تنفيذ السند (SA-03).
**UC-FIN-04 · ضبط السنة المالية وشجرة الحسابات وتصنيفات المصروفات** — بدون افتراض ربط بدفتر خارجي (بند 40).
**UC-FIN-05 · سياسة التأخير** — تنبيه ثم تحويل الحالة لمراجعة المبيعات/المالية، **بدون إيقاف تلقائي بمدة افتراضية** (بند 41) · المدة **{Open}**.

**US-FIN-01** AC: تغيير الضريبة لا يعدّل فواتير صادرة · أي تغيير بـStep-up.
