## SA-16 · صندوق الاعتمادات — P0 · [Approved كمفهوم، السلسلة Pending]

**Epic story:** كصاحب شركة أريد مكان واحد أشوف فيه كل اللي مستني قراري، وأقرر بسرعة وبسبب مسجّل.

### الشاشات
| ID | الاسم | Route |
|----|-------|-------|
| SCR-INB-01 | صندوق الاعتمادات (قائمة موحدة) | `/super-admin/approvals` |
| SCR-INB-02 | تفاصيل الطلب + السياق (لوحة جانبية) | `/super-admin/approvals/:id` |
| SCR-INB-03 | حوار القرار (اعتماد/رفض/طلب تعديل/تفويض) | Dialog |

**الأنواع:** خصم يتجاوز الحد · طلب كبير · قائمة أسعار [New] · سند صرف · مرتبات · تجاوز تسجيل تاجر. **أعمدة:** النوع · مقدّم الطلب · المبلغ/الأثر · العمر (SLA **{Open}**) · تقدّم السلسلة (Sales Manager ← General Manager) · إجراءات. فلاتر: النوع · الحالة · المقدّم · المدى.

### Use Cases
**UC-INB-01 · اعتماد طلب** — فتح الطلب ← مراجعة السياق (العميل، البنود، الخصم، الأثر) ← اعتمد ← (Step-up لو مالي) ← الطلب يكمل أو ينتقل للخطوة التالية ← `APPROVAL.APPROVED`.
- استثناءات: الطلب اتغيّر بعد ما فتحته ← تحذير «تغيّر الطلب» ويلزم المراجعة من جديد · الصلاحية اتسحبت ← 403.
**UC-INB-02 · رفض** — سبب إلزامي يصل لمقدّم الطلب ← `APPROVAL.REJECTED`.
**UC-INB-03 · طلب تعديل [New]** — يرجّع الطلب للمقدّم مع ملاحظة ← `CHANGES_REQUESTED`.
**UC-INB-04 · تفويض [New]** — إسناد لشخص عنده `sa.approvals.approve` ← `DELEGATED`.
**UC-INB-05 · اعتماد من الموبايل** — الإشعار يفتح الشاشة ← التطبيق يتحقق من الجلسة والصلاحية والحالة الحالية ← يعرض الإجراء إن سُمح (بند 17). **لا اعتماد من نص الإشعار.**

### User Stories + AC
- **US-INB-01** كمدير نظام أريد قائمة موحدة للاعتمادات. AC: مرتّبة بالأقدم/الأهم · عدّاد على الجرس والقائمة.
- **US-INB-02** كمدير نظام لا أريد أعتمد طلبي أنا. AC: زر الاعتماد معطّل بسبب «لا يمكنك اعتماد طلبك» (فصل المهام [New]).
- **US-INB-03** كمدير نظام أريد أعرف سلسلة الاعتماد. AC: Stepper يبيّن مين اعتمد ومين الدور عليه.
- **BR-INB-01** كل قرار بسبب ويتسجّل. **BR-INB-02** لا اعتماد مالي دون الصلاحية المطلوبة (Approved بند 25).

## SA-17 · سجل التدقيق (Audit Log) — P0 · [Pending بند 35] (الاحتفاظ [Open])

**Epic story:** كصاحب شركة أريد أعرف مين عمل إيه وإمتى وكان إيه قبل وبعد، بشكل لا يمكن تغييره.

### الشاشات
| ID | الاسم | Route |
|----|-------|-------|
| SCR-AUD-01 | سجل التدقيق (قائمة + فلاتر) | `/super-admin/audit` |
| SCR-AUD-02 | تفاصيل الحدث + Diff قبل/بعد | Drawer |
| SCR-AUD-03 | تصدير (CSV/PDF) | Dialog |

**أعمدة:** الوقت · المستخدم · الإجراء · الهدف (رابط) · قبل · بعد · IP/جهاز [New] · النتيجة [New] · الخطورة [New]. **فلاتر:** مدى زمني · مستخدم · فئة · نوع الهدف · نتيجة · خطورة · بحث نصي.

### Use Cases
**UC-AUD-01 · البحث والفلترة** — مدى زمني + فئة ← نتائج مرقّمة بترتيب زمني عكسي.
**UC-AUD-02 · فتح تفاصيل حدث** — Diff يظلّل القيم المتغيرة (نص/رقم/JSON) + بيانات الجلسة والجهاز.
**UC-AUD-03 · تصدير** — `sa.audit.export` ← Step-up ← ملف ← **التصدير نفسه يُسجَّل** `EXPORT.AUDIT`.
**UC-AUD-04 · تسجيل حدث (سلوك النظام)** — كل شاشة/خدمة تكتب حدثها مع قبل/بعد في نفس المعاملة (transaction) مع العملية؛ فشل الكتابة = فشل العملية للأحداث الحساسة [New].
**UC-AUD-05 · محاولة تعديل/حذف** — غير متاحة في الواجهة؛ الـAPI يرفض (append-only).

### AC
- **US-AUD-01** AC: لا يوجد أي زر تعديل/حذف · الصفحة تعرض أيقونة قفل "للقراءة فقط".
- **US-AUD-02** AC: كل حدث في [كتالوج الأحداث](00-foundation-and-catalogs.md) يظهر بالمستخدم والوقت والإجراء وقبل/بعد.
- **US-AUD-03** AC: الأداء مع آلاف السجلات: pagination على الخادم، بحث مفهرس.
- **مفتوح:** مدة الاحتفاظ · القائمة النهائية للأحداث الحساسة · هل يُحفظ IP (خصوصية).
