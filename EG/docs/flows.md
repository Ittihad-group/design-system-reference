# Key flows

> Status: scaffold — diagram each flow before UI polish

## Auth

1. Login (بريد + كلمة مرور) → session → landing حسب الدور (RBAC)
2. نسيت كلمة السر → استعادة ذاتية بالبريد أو طلب إعادة تعيين من Super Admin (Pending Confirmation)
3. خمول → قفل تلقائي → إعادة تحقق (بصمة/PIN لاحقاً)

## Sales order

1. Customer select → lines → submit → **مراجعة** → confirm (بصلاحية الاعتماد) → payment status
2. خصم أو طلب كبير → اعتماد بصلاحية محددة قبل التأكيد

## Create Your Order (Public Catalog → Dealer Portal) — Approved

1. Public Catalog → زر «أنشئ طلبك»
2. تسجيل الدخول — تاجر مسجل يدخل بحسابه · عميل جديد ينشئ حساباً ويرسل طلب تسجيل كتاجر (يوافق عليه فريق المبيعات)
3. إضافة المنتجات → تحديد الكمية والمقاس واللون (التاجر يرى أسعاره، والفاتورة المبدئية تتكوّن أمامه لحظياً)
4. مراجعة الطلب والفاتورة المبدئية + تأكيد رقم الهاتف وأنسب وقت للاتصال → إرسال ← رسالة «سيتصل بك أحد ممثلي المبيعات لتأكيد الطلب»
5. يُنشأ طلب جديد في النظام ويظهر في المبيعات كمهمة اتصال: يتصل ممثل المبيعات بالتاجر، يراجع الأصناف والأسعار، يسجّل نتيجة الاتصال، ثم يؤكّد بصلاحية (لا تأكيد تلقائي)
6. التاجر يتابع الحالة، يعيد الطلب من سابق، يرى عروض الأسعار والفواتير المسموحة له

## Invoice to cash (Pending Confirmation)

1. عرض سعر ← أمر بيع (تأكيد بصلاحية) ← إذن تسليم ← فاتورة (مسودة ← صادرة)
2. تحصيل (نقداً · تحويل · شيك) ← سند قبض يُرحَّل للحسابات ← تحديث المتبقي (جزئي/مدفوع)
3. تأخر عن الاستحقاق ← تنبيه ثم تقييد أوامر جديدة (الحدود Pending) ← أعمار الديون وكشف الحساب
4. الفاتورة الإلكترونية منفصلة عن الإصدار الداخلي (Pending)

## Attendance to payslip (Pending Confirmation)

1. حضور وانصراف ← مراجعة ← حساب المرتبات (مكونات Pending)
2. اعتماد (HR + الحسابات، بصلاحية Approve) ← سند صرف ← مفردات كل موظف (سرية)
