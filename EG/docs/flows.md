# Key flows

> آخر تحديث: 2026-11-03 · الحالات: **Approved** / **Pending Confirmation** (اقتراح يحتاج اعتماد الجهة) / **Open**. أرقام البنود من [`open-questions.md`](open-questions.md). القيم المقترحة **إعدادات قابلة للتعديل** وليست قواعد ثابتة.

## Auth

1. Login (بريد + كلمة مرور) → session → landing حسب الدور (RBAC).
2. نسيت كلمة السر → **رابط مؤقت إلى البريد المسجل** لإعادة التعيين (Pending — IT، بند 15)، أو إعادة تعيين من Super Admin.
3. خمول **30 دقيقة (قيمة مقترحة)** → قفل/انتهاء جلسة → إعادة تحقق؛ والعمليات الحساسة تطلب إعادة تحقق (Pending — IT). بصمة/PIN لاحقاً وخارج v1 قبل اعتماد IT (بند 16).
4. حساب التاجر: **منفصل عن RBAC الداخلي** (Pending، بند 34). لا يُفعَّل بالتسجيل الذاتي؛ يعتمده فريق المبيعات (بند 32).

## Super Admin — الأمان والتدقيق (Pending — الإدارة / IT، بند 35)

1. حساب Super Admin أساسي لصاحب الشركة + حساب احتياطي لشخص تسميه الإدارة، مع MFA وإمكانية تعطيل الحسابات.
2. كل حدث حساس (دخول فاشل، تغيير صلاحيات، اعتماد، صرف، تعديل إعدادات) يُسجَّل في **Audit Log**: المستخدم · الوقت · الإجراء · القيم قبل/بعد.
3. السجل للقراءة فقط: لا تعديل ولا حذف من الواجهة. مدة الاحتفاظ: Open (الإدارة وIT).

## Sales order

1. Customer select → lines → submit → **مراجعة** → confirm (بصلاحية الاعتماد) → payment status.
2. الخصم أو الطلب الذي يتجاوز **الحد المحدد في الإعدادات** (القيم Open، بند 33) أو يحتاج استثناءً ← **Sales Manager** ← **General Manager** إن تطلبت مصفوفة الاعتماد. لا أرقام ثابتة.

## Create Your Order (Public Catalog → Dealer Portal)

**Approved (بنود 26 و27 و48):** لا تأكيد تلقائي · التاجر يرى أسعاره وتتكوّن فاتورته المبدئية أمامه · بعد الإرسال «سيتصل بك ممثل المبيعات لتأكيد الطلب».
**Pending Confirmation — المبيعات / فريق المنتج (بنود 31 و32 و50):**

1. الزائر يتصفح الكتالوج: **مواصفات بلا أسعار** (لا أسعار عامة للزائر).
2. يضغط «أنشئ طلبك» ← **شاشة تسجيل الدخول**. لا إنشاء ولا إرسال طلب كزائر.
3. تاجر معتمد: يدخل ← يعود مباشرة إلى إنشاء الطلب.
4. لا حساب؟ **طلب فتح حساب** منفصل ← حالة «قيد مراجعة المبيعات» ← يعتمد فريق المبيعات (أو يرفض) ← بعد الاعتماد فقط يسجّل الدخول ويكمل الطلب.
5. إضافة المنتجات ← الكمية والمقاس واللون ← **أسعار التاجر (قائمة مرتبطة بكل تاجر)** ← الفاتورة المبدئية تتكوّن لحظياً.
6. مراجعة الطلب والفاتورة + تأكيد رقم الهاتف وأنسب وقت للاتصال ← إرسال ← رسالة «سيتصل بك ممثل المبيعات».
7. المبيعات: مراجعة الطلب ← **تواصل هاتفي مع التاجر** ← تسجيل نتيجة الاتصال ← تأكيد الطلب بصلاحية، أو تواصل إضافي. مهلة الاتصال ومن يتصل وماذا يحدث عند عدم الرد: **Open (بند 49)**.
8. التاجر يتابع الحالة، يعيد الطلب من سابق، ويرى عروض الأسعار والفواتير المسموحة له.

## Invoice to cash (Pending Confirmation — دورة مقترحة للتخطيط)

1. عرض سعر ← أمر بيع (تأكيد بصلاحية) ← إذن تسليم ← فاتورة (مسودة ← صادرة).
2. تحصيل بالخيارات المفعّلة من إعدادات المالية (نقداً · تحويل بنكي · شيك · بطاقة) ← سند قبض يُرحَّل للحسابات ← تحديث المتبقي (جزئي/مدفوع). **الشيك:** مستلم ← تحت التحصيل ← محصَّل / مرتد / ملغى (بند 39).
3. تأخر العميل: **لا إيقاف تلقائي بمدة افتراضية.** تنبيه عند التأخير ثم تحويل الحالة إلى مراجعة المبيعات/المالية. مدة التنبيه وحدود الإيقاف: Open، تعتمدها الإدارة (بند 41).
4. الدفع للموردين: **سند الصرف بثلاث صلاحيات منفصلة: إنشاء ← اعتماد ← تنفيذ**، وأكثر من حساب بنكي وخزينة. الحدود من مصفوفة معتمدة بلا مبالغ افتراضية (بند 42).
5. الفاتورة الإلكترونية منفصلة عن الإصدار الداخلي (Approved)؛ **التنفيذ معلّق** حتى تؤكد المالية التسجيل والشهادة وتحدد المسؤول الفني (بنود 12 و43). لا يُوصف النظام بأنه متكامل قبل اختبار واعتماد التكامل. ملف PDF العادي ليس فاتورة إلكترونية.
6. الضريبة: النسبة وطريقة العرض (شاملة/غير شاملة) والإعفاءات **إعدادات** يعتمدها المحاسب القانوني؛ 14% في الديمو تجريبية (بند 38). السنة المالية وشجرة الحسابات وتصنيفات المصروفات إعدادات (بند 40).
7. ترقيم المستندات: بادئات أولية قابلة للتعديل، بلا تكرار وبتسلسل لكل نوع (بنود 14 و47)، غير نهائية قبل اعتماد المالية والتشغيل.

## Attendance to payslip (Pending Confirmation)

1. مصدر حضور واحد يختاره HR (مع دعم مصادر أخرى مستقبلاً) ← مراجعة ← حساب المرتبات من **مكونات قابلة للتكوين** (أساسي، إضافي، خصومات، سلف، تأمينات، ضريبة). لا حساب قانوني تلقائي قبل اعتماد القواعد (بند 44).
2. اعتماد (HR + الحسابات، بصلاحية Approve) ← سند صرف (بالصلاحيات المنفصلة) ← مفردات كل موظف (سرية).
3. عرض الأجور: HR ومن تمنحه الإدارة صلاحية صريحة؛ General Manager ليس تلقائياً (بند 46). سياسة التأخير والإجازات تُعتمد قبل التفعيل (بند 45).

## Mobile — الإشعارات والإجراءات

1. حدث في النظام ← **الـBackend يقرر** هل يُرسل إشعاراً ولمن (بند 17) ← FCM/APNs ينقلان الإشعار فقط.
2. المستخدم يفتح الإشعار ← يفتح التطبيق على الشاشة المعنية ← **يتحقق من الجلسة والصلاحية والحالة الحالية للطلب** ← يعرض زر الإجراء إن كان مسموحاً. **لا يُنفَّذ اعتماد أو إجراء حساس من نص الإشعار نفسه** (Approved، بند 25).
3. التصنيف: Urgent (أعطال/ما يوقف العمل) · Action (مهام تتطلب إجراءً) · Info (تحديثات عامة) — Pending (بند 18). الأحداث والمستلمون وساعات الهدوء **غير مفعّلة** قبل اعتماد التشغيل.

## Mobile — Offline (Pending — التشغيل، بند 9)

1. بدون اتصال: عرض البيانات المحمّلة مسبقاً وحفظ **مسودات غير حساسة فقط**.
2. لا اعتماد ولا صرف ولا تعديل مخزون نهائي دون اتصال (Approved جزئياً، بند 30).
3. عند المزامنة: إن تغيّرت البيانات على الخادم، **يُعرض التعارض للمستخدم ليقرر**، ولا تُكتب النسخة المحلية فوق الأحدث تلقائياً.
