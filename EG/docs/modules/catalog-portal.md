# Module — catalog-portal (الكتالوج وبوابة التاجر)

> Status: **Approved** (الفكرة والقواعد) · Live: `../../catalog.html` · مكونات: `../../design-system.html#catalog` · المتطلبات: `../../PRODUCT.md` (قسم 5)

## Purpose

الكتالوج جزء من النظام: رابط عام للمنتجات، وإنشاء طلب من التاجر، وبوابة لمتابعة الطلبات. بديل لملف PDF.

## Users

زائر / عميل جديد · تاجر مسجل (Dealer — دور خارجي منفصل عن RBAC الداخلي، افتراض Open) · فريق المبيعات (للمراجعة والتأكيد).

## Primary screens

| Screen | Anchor in `catalog.html` | Notes |
|--------|---------------------------|-------|
| الكتالوج العام | `#catalog` | تصفح، بحث، تصفية بنوع المنتج، مشاركة؛ زر «أنشئ طلبك» = Accent الوحيد |
| صفحة المنتج | `#product` | 11 تشطيباً، المقاسات، الكمية بالوحدة، سعر عام/تاجر، رابط مشاركة |
| أنشئ طلبك | `#order` | **ديناميكي:** يرى التاجر أسعاره، تتكوّن الفاتورة المبدئية أمامه، ثم مراجعة وتأكيد رقم الهاتف، ثم رسالة «سيتصل بك ممثل المبيعات» (`js/order-demo.js`) |
| بوابة التاجر | `#portal` | طلباتي، إعادة الطلب، عروض الأسعار، الفواتير والمدفوعات المسموحة |
| مراجعة المبيعات | `#review` | مهمة اتصال بالتاجر ثم تسجيل النتيجة والتأكيد بصلاحية Approve |

## Flow (Approved)

1. «أنشئ طلبك» ← تسجيل الدخول. 2. تاجر مسجل يدخل · عميل جديد ينشئ حساباً ويرسل طلب تسجيل تاجر. 3. إضافة المنتجات. 4. الكمية والمقاس واللون. 5. مراجعة الطلب. 6. إنشاء طلب جديد في النظام. 7. يظهر في المبيعات للمراجعة والتأكيد.

## Rules (Approved)

- التاجر يرى أسعاره أثناء بناء الطلب، والفاتورة المبدئية تتكوّن أمامه ديناميكياً.
- بعد الإرسال يُبلَّغ أن أحد ممثلي المبيعات سيتصل به هاتفياً لتأكيد الطلب (بند 48).

- لا تأكيد تلقائي للطلب.
- أسعار خاصة بالتجار عند الحاجة؛ الأسعار والخصومات حسب سياسات الشركة وصلاحيات المستخدم.
- لا يرى التاجر بيانات عملاء آخرين ولا التكاليف الداخلية.
- الكتالوج يتحدّث من إدارة المنتجات داخل النظام.
